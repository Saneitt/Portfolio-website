01 / THE PROBLEM

An assistant you speak to.
A system that can act.

I wanted a useful presence on my own computer: something I could address naturally, ask to do real work, and leave closed when I did not need it.

The first design put a conversation beside a plan canvas. It felt too much like another language-model interface. I moved the centre of the experience to a voice core, a concise caption and a compact schedule.

Making that direction real meant solving speech capture, turn taking, tool execution, local inference and Windows lifecycle behaviour together. The prototype supplied the visual language; the application needed dependable state behind it.

02 / DECISIONS

Continuity matters
more than a chat history.

Wake once, then converse

The wake phrase opens a conversation from standby. Follow-up listening remains active after the assistant replies, so every request does not need another “Hey Jarvis.” Voice interruption, the central core and Escape provide ways to take the turn back.

Keep the next action visible

The right column shows a month calendar and a selected-day agenda. Voice and direct editing use the same SQLite records. Notes, all-day events, reminders and advance alerts make the edge of the interface useful between conversations.

03 / INSIDE THE LOOP

Local speech.
Local reasoning.
Real operations.

01 / HEAR

Wake and capture

openWakeWord detects the name in standby. Voice activity detection and faster-whisper turn an utterance into text without a cloud speech service.

02 / UNDERSTAND

A replaceable brain

Ollama serves Qwen3.5 and structured tool calls. The interface, tools, memory and calendar are independent of the chosen weights.

03 / ACT

Use the computer

Tools work with files, open applications, inspect system status, control media, manage calendar records and run approved PowerShell.

04 / RESPOND

Prepare speech ahead

Kokoro or Piper generates local speech. Short sentences are grouped and decoded ahead; playback continues until the last buffer finishes.

04 / AUDIO REFINEMENT

A smooth voice needs
a smooth delivery path.

The voice sounded clipped in conversation, while a standalone sample played smoothly. That distinction changed the debugging direction.

I preserved generated clip endings, grouped short sentences and scheduled upcoming clips on the audio clock. An isolated Test voice control lets someone preview the engine, voice and speed before saving, with microphone input paused for the sample.

Playback checks verified complete buffers and no measurable scheduling gap between prepared clips. Listening feedback on the development laptop confirmed an improvement. Real rooms, accents and overlapping speech still need wider testing.

05 / CONTROL

Useful access.
Specific decisions.

File overwrites, moves, deletes, unknown program launches and PowerShell surface a concrete approval. Activity records actual results and failures. File overwrites retain backups; interruption cancels pending output rather than pretending a completed operation has been undone.

The assistant runs under the user's Windows account. Local processing does not make every action correct. The application validates tool arguments, bounds work and keeps approval state separate from the model's wording. Calendar data stays local; external account sync is outside this version.

06 / THE WINDOWS HANDOFF

Launch like an app.
Close like an app.

A dedicated WebView2 window gives Jarvis a taskbar icon and Start menu entry. Its services belong to that window's lifetime.

Closing the window stops the microphone, backend and model runners. Windows kernel ownership covers an abnormal exit too. There is no always-on tray service or login startup. A closed assistant should not reserve a laptop's compute.

The guided installer detects RAM and NVIDIA VRAM, then offers Qwen3.5 sizes from 0.8B to 35B MoE. Only the chosen model is downloaded. A text-only 4B profile is the tested default for my 4 GB GPU; larger choices need validation on their target hardware.

07 / VERIFICATION

What is working.
What still needs evidence.

Checked in this build

Automated tests cover tool validation, persistent records, calendar alerts, date boundaries, file operations, approval state, speech grouping and scheduled playback. Native-window checks cover event editing and actual speech. Shutdown checks confirmed no remaining Jarvis processes or service listeners.

The recommended 4B setup completed on the development laptop, including model preparation, speech downloads, native build and Start menu registration.

The next validation

A broader usability study, more accents and noisy rooms, and measurements on other hardware tiers. External calendar sync, connected email and autonomous visual desktop navigation remain future work.

This project was developed with AI assistance. Product direction and iteration came from hands-on use and implementation feedback, not a completed formal user-research study.
